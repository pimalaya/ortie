# A refusal carries its code

Ortie meets the family's failure contract: a command line the grammar refuses exits 2 and, under `--json`, prints the failure object coded `usage-invalid`; a failure a caller acts on carries a stable `code`, the OAuth refusals named by what the caller does next. Three commits.

## Phase 1, the libraries (9735d5c)

Cargo.toml requires io-oauth 0.7 and pimalaya-stream 0.4 together (io-oauth 0.7's `Oauth20ClientStd::connect` takes stream 0.4's `Tls`), and pins pimalaya-cli at 0be1b1f08d19ccb9d16ee8e1d4266c27c96e0cdd in `[patch.crates-io]`, until pimalaya-cli 0.4.1. `cargo update` took pimalaya-config 0.4.1, whose prompting credential command reads the terminal. src/config.rs fills the `Tls` it builds with `server: None, client: None`: `tls` stays a provider name, and Ortie gains no client certificate option (RFC 8705 is not io-oauth's). `cargo tree -d --all-features -e normal` lists one pimalaya-stream, io-http and io-oauth.

## Phase 2, the refused line (0526c2c)

src/main.rs parses through pimalaya-cli's `clap::parse`: a refused line exits 2, printing the failure object coded `usage-invalid` on stdout when a `--json` word comes before any `--`, clap's rendering on stderr otherwise. A piped REPL line clap refuses is coded `usage-invalid` by pimalaya-cli and loses its `Error: error:` prefix. The MCP server's own argument refusals (a missing or non-string argument) are coded `usage-invalid` through `CodedError::new(CommonCode::UsageInvalid, ..)`, as pimalaya-cli codes an undeclared one. tests/exit.rs covers the binary: `--json token show --nope` (one coded object on stdout, exit 2), the same without `--json` (stderr only), `--json` after `--` (an argument), and help under `--json` (exit 0).

## Phase 3, the codes

src/error.rs holds `ErrorCode`: `permission-denied`, `rate-limited`, `grant-invalid`, `client-invalid`, `client-unauthorized`, `scope-invalid`, `device-code-expired`, `state-mismatch`, `token-missing` and `endpoint-missing`, beside pimalaya-cli's `usage-invalid`, which `ErrorReport` still falls back on through `CommonCode`.

- The OAuth error bodies (io-oauth's `Oauth20AccessTokenErrorParams`, `Oauth20AuthErrorParams` and `Oauth20TokenRevokeErrorParams`) are no `std::error::Error`, so each is coded where Ortie turns it into a failure, by `error::oauth_error`: auth get's device authorization and device poll, auth resume's redirect and code exchange, `client_credentials_error` (the JWT renewal hint kept as the innermost cause), token refresh, token revoke and the MCP device poll. The message names the code as the server spelled it, `(code invalid_grant)` where `{:?}` printed `(code InvalidGrant)`, and `(unregistered code)` for one io-oauth drops into `Unknown` (Google's `invalid_token` on a revoke).
- io-oauth's token and revocation code enums derive `Deserialize` only, so the wire spelling is an exhaustive match in src/error.rs, which a unit test reads back through io-oauth's own serde names, every variant.
- The codes io-oauth's typed client error names, `Oauth20ClientStdError::DeviceCodeExpired` (the local deadline, of `auth get` and of the MCP device flow) and a bare `Status(403)` or `Status(429)` of any request, are read by `error::code` walking the chain. `pimalaya_cli::error::ErrorReport` reads only `code_of`, so every failure path passes its error through `error::with_code`, which rebuilds the chain's messages unchanged over a coded innermost one: src/main.rs (`ErrorReport::<ErrorCode>::eval_coded`), src/cli.rs (`exit_on_failure::<ErrorCode, _>`), src/repl.rs (`repl.run::<_, ErrorCode>`), and src/mcp.rs (`ToolResult::printed`, `ToolResult::error`, and the `error_object` the failed flows hold, so `auth_status`'s nested `error` carries the code).
- `state-mismatch` codes a redirect carrying no `state` or another one (src/auth/resume.rs); the issuer check stays uncoded. `endpoint-missing` codes a missing `endpoints.authorization`, `endpoints.device-authorization`, `endpoints.token` or `endpoints.revocation` (src/auth/get.rs, src/auth/resume.rs, src/token/refresh.rs, src/token/revoke.rs). `token-missing` codes a refresh without a refresh token (src/token/refresh.rs) and a read command printing nothing, exiting 0 or, as `secret-tool lookup` does, non-zero without a word (src/account.rs `read_storage`), where an empty storage failed with a JSON parse error; a read command failing with a message stays uncoded, and a failed storage write is no missing token.
- `json-schema`'s `ortie-error` types `code` by `ErrorCode` and `usage-invalid`, and so does the `error` of the MCP `auth_status` answer.
- "No authorization code flow is pending" (MCP `auth_resume`) and a connection refused by a closed port stay uncoded, the vocabulary having nothing for them: tests/mcp.rs and tests/repl.rs keep asserting `code: null`.

Evidence: tests/token_revoke.rs `a_refused_refresh_token_is_coded_grant_invalid` and `a_bare_403_or_429_is_coded_by_its_status` (refresh and revoke, each status), tests/client_credentials.rs `invalid_client_is_coded_client_invalid`, tests/device_grant.rs `a_denied_device_is_coded_permission_denied` and `an_expired_device_code_is_coded_device_code_expired` (through `auth resume` against the mock refusing every poll), tests/mcp.rs `a_device_flow_past_its_deadline_is_coded_device_code_expired` (the local deadline, read from `auth_status`), tests/codes.rs (`token show` on an empty storage and `token refresh` without a refresh token, a missing `endpoints.revocation`, a redirect of another state or none), and src/json_schema.rs `the_error_schema_names_the_codes`. Each asserts a code the failure object printed `null` for before the phase; the bare-status test also fails with `error::with_code` taken out of src/main.rs. tests/token_revoke.rs `a_rejected_revocation_fails_with_its_code` and tests/client_credentials.rs `invalid_client_on_the_jwt_kind_hints_certificate_renewal` match the wire spelling, as do the live tests/google.rs and tests/microsoft.rs (built, not run, which also assert `client-invalid`). `cargo fmt`, `cargo test --all-features`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo clippy --all-targets --no-default-features --features rustls-ring -- -D warnings` and `cargo deny check` pass. The live suites wait on the owner.

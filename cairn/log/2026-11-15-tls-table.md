# The `tls` table, and the configuration on the family's shapes

`tls` is the table every Pimalaya CLI reads: `tls.provider`, `tls.rustls.crypto` and the new `tls.cert`, folded by `TlsConfig::into_tls`. The 2.x string is refused by name through `pimalaya_config::toml::Removed` in the family sentence, naming the keys its value becomes; the `hooks` table is refused through `removed_key!`. The storage commands are pimalaya-config's `CommandConfig`, `cmd` still its alias. config.sample.toml carries the `tls.*` lines, all commented.

Evidence: `the_tls_string_is_refused_naming_its_keys` fails on the string enum, which read the four values; tests/account.rs `the_tls_string_is_refused_by_name` checks the sentence through the binary; `tls_and_alpn_fold_into_one_handle` covers `tls.cert`; the sample test parses every `tls.*` variant.

Renamed configuration key: `tls` (string) to `tls.provider` and `tls.rustls.crypto`.

Capabilities moved: config ("Storage commands", "v1 config compatibility", "One TLS conversion, taking the ALPN list", "One sample configuration, with a section per provider", "The configuration refuses every key it does not read").
